# Researcher

**一个模块化的信息搜索与整理引擎。** 输入一个问题，它自动完成
`搜索 → 抓取正文 → 整理合成 → 输出报告`，并给出带引用与来源记录的成品；
界面是一个 Electron 桌面应用。

> **状态：代理式架构已落地。** 引擎、插件、桌面应用都可运行，**278 个测试通过**，
> 界面冒烟、真实加密落盘、真实页面抽取回归网均已验证。见文末「已知限制」。

---

## 这个项目在解决什么

把「用大模型做资料调研」这件事从**一次性对话**变成**可替换、可复现、可追溯的流水线**：

| 常见做法的问题 | 这里的做法 |
|---|---|
| 换个搜索源就要改代码 | 搜索是插件，换后端 = 改配置 |
| 报告说不清用了什么模型、哪些来源抓失败了 | 每次运行都写 `provenance.json`，报告里逐条标注来源状态 |
| 一次失败整轮白跑 | 阶段降级（LLM 失败→抽取式整理）、抓取失败不致命、产物 append-only |
| 界面和引擎焊死 | 内核不认识 Electron；同一套引擎也能用 `node scripts/run-example.ts` 直接跑 |
| 没配 API key 就什么都看不到 | 零 key 也能跑完整链路（DuckDuckGo + 抽取式整理） |

## 核心设计：一切皆插件

内核**不含任何领域知识**——它不知道「搜索」背后是 DeepSeek 还是 DuckDuckGo，
只知道配置里写着哪个 id、那个插件是否 `available()`。插件之间**从不互相 import**，
只通过内核上下文（`ctx`）协作。

```
用户查询
   │
   ▼
┌──────────────────────────── Kernel（内核，稳定不变） ────────────────────────────┐
│  registry 插件注册表 · selection 运行期选型 · config 设置                        │
│  run-store append-only 产物 · events 进度事件 · fetch 抓取+正文抽取 · errors 类型化错误 │
└───────────────────────────────────┬──────────────────────────────────────────────┘
                                    │  插件只依赖 src/main/engine/types.ts 这一份契约
        ┌───────────────┬───────────┼───────────────┬────────────────┐
        ▼               ▼           ▼               ▼                ▼
   pipeline/        search/     provider/      organize/        output/
   主流程           搜索         大模型          整理              输出
```

四类插件（外加作为消费方的输出），每一类都可以整体替换：

| 类别 | 契约 | 内置实现 |
|---|---|---|
| `pipeline` | `available(ctx)` + `run(input, ctx, signal) → Report` | `pipeline-research`（代理式调研）、`pipeline-default`（线性四阶段，免大模型） |
| `search` | `search(req, ctx, signal) → SearchResult` | `search-deepseek`（原生 web_search）、`search-duckduckgo`（免 key） |
| `provider` | `complete(req, ctx, signal) → CompleteResult` | `provider-openai`（任何 OpenAI 兼容端点，支持原生工具调用） |
| `organize` | `organize(input, ctx, signal) → OrganizeOutput` | `organize-llm`（严格 JSON）、`organize-extractive`（免 key） |
| `output` | `render(report, ctx, signal) → Artifact[]` | `output-markdown`、`output-html`、`output-json` |

**「可替换」的含义**：插件代码在启动时静态注册（编译进主进程 bundle），
**运行期由配置决定谁是活动的**——这与 DSH 的做法一致：可替换性来自统一接口 + 运行期选型，
而不是把第三方代码热加载进来。加一个插件＝写一个目录 + 在 `src/plugins/index.ts` 登记一行。

## 两条主流程

`pipeline-research`（默认）与 `pipeline-default` 产出**完全相同的 `Report`**，
因此三个输出插件一行都不用改。没有大模型 key 时前者 `available()` 为假，
内核自动降到后者——零 key 路径就是这么保住的。

### `pipeline-research`：任务，不是流水线

这里**没有「第 1 步做什么、第 2 步做什么」**。每个 agent 是一个**任务**：
拥有目标 + **自己观测得到的终止条件**；任务之间不通过顺序连接，只通过一份共享的**黑板**互相影响。

```
共享黑板：语料 · 主题地图（只增不减）· 大纲 · 已写小节 · 缺口请求 · 观测日志
              ▲                                    │
   ┌──────────┴──────────┐              ┌──────────┴──────────┐
   │ 搜索任务             │              │ 大纲任务             │
   │ 终止：地图饱和       │◀── 缺口请求 ──│ 终止：覆盖度达标     │
   │ （连续 N 轮新内容    │              │ （固定节在位、每节   │
   │   贡献率低于阈值）   │── 补完即结清 ▶│   支撑够、无遗漏主题）│
   └─────────────────────┘              └─────────────────────┘
                                                  │
                                       ┌──────────┴──────────┐
                                       │ 写作任务             │
                                       │ 终止：全部小节自检通过│
                                       │ 工具：补搜/回读/改大纲│
                                       └─────────────────────┘
```

运行器做**不动点迭代**：反复问「还有谁没满足」，让没满足的走一步。任务可以**互相重新激活**——
大纲发现某节支撑不足时不去自己搜，而是往黑板写一条**缺口请求**，搜索任务看到未处理的请求就
重新变得未满足。整轮在所有任务**同时满足**时结束。

**终止条件来自观测，不是步数**：

| 任务 | 它怎么知道自己该停 |
|---|---|
| 搜索 | 连续 N 轮「新增地图内容 / 本轮并入文档数」低于阈值（默认 2 轮 / 0.3），且无未处理缺口请求 |
| 大纲 | 模板要求的固定节都在、可展开节够数、每节支撑来源 ≥ 下限、地图上没有主题被漏掉 |
| 写作 | 每一节都写出来了，且通过了针对模板要求的自检 |

配置项配的是**阈值**（饱和率、支撑下限、自检标准）。`globalIterations` / `maxToolSteps` 只是
防死循环的**护栏**，设得远超正常所需；撞上时如实报告「条件未满足就停了」，不假装完成。

### 广度优先，只淘汰重复与无关

从结果倒推需求：写作要的资料**质量要求不苛刻但格式严格**，大纲需要**结构化的全面视野**，
搜索要的是**广度与深度**。所以筛选**禁止按质量排序**——淘汰赛会杀掉大纲唯一需要的广度。
过滤只做两件事：确定性去重（URL / 同域名同标题 / 正文近似），以及让模型挑出**无关**项
（提示词明确要求它只输出无关的下标，不许排名）。判定失败时**整批保留**：多留噪声的代价远小于误删资料。

被过滤的条目**仍出现在报告的来源清单里**并标注原因——筛必有漏，藏起来比漏掉更糟。

### 文档模板

`lecture`（讲义）、`report`（综述）、`brief`（简报）。一份模板同时约束
**大纲必须包含哪些节**（固定节）与**每节该怎么写**。设置里可切换。

### 正文抽取

`@mozilla/readability`（Firefox 阅读模式的算法，零依赖）+ linkedom。
实测四个真实页面赢三个，但在重前端框架的页面上会只取到页脚——所以有一条**升级—回退链**：
Readability 结果低于闸门（绝对下限 400 字，或不足整页文本的 20%）时回退到**整页纯文本**。

回退刻意选「整页纯文本」而不是再写一个启发式抽取器：下游是 LLM 代理，它有能力忽略导航噪声；
而一个把正文猜错的智能抽取器会**主动丢内容**——噪声可以忽略，丢掉的东西找不回来。

用了哪个实现会逐篇记录并进入 provenance。想现场核对：
`node --no-warnings scripts/check-extraction.ts`。

### 话题缓存

`<数据目录>/topics/<topicId>/{topic.json, board.json}`。同一话题再次研究时读回语料与地图，
**复用不需要任何特例**——地图已经填满，正是搜索任务原本就认作「饱和」的条件，于是它自己就早收工，
只补真正新增的部分。复用了什么会写进 provenance 与运行摘要，
报告绝不会悄悄依赖几周前采集的材料。

缓存读不出来时按「没有缓存」处理并从零开始；写入用临时文件 + rename，中断不会留下半截缓存。

### 降级：不是「尽力而为」，而是如实记录

选型阶段：主插件 `available()` 为假 → 自动用配置的备用插件。
运行阶段：整理插件抛错 → 用备用整理插件重跑，并把原因写进 `provenance.degraded`。

报告与 `provenance.json` 永远写明**实际**用了哪个插件、是否降级、为什么降级。

```bash

pnpm typecheck     # 主进程 + 渲染进程分别类型检查
```

### 配置大模型

两种方式，任选其一：

1. **环境变量**（推荐，完全不落盘）：启动前设置 `DEEPSEEK_API_KEY`。
2. **应用内设置**：右上角「设置」→ 填 Base URL / 模型 / API Key（**加密保存**，见下）。

默认端点是 `https://api.deepseek.com/v1`（OpenAI 兼容），默认模型 `deepseek-chat`。
换成 OpenAI、vLLM、Ollama 或自建网关，只改 Base URL 与模型名即可。

### 零 key 也能跑

不配置任何 key 时：搜索自动降级到 DuckDuckGo，整理自动降级到抽取式。
两条降级都会在报告里如实标注。

## API Key 怎么存

**密钥明文既不写入配置文件，也不下发到界面。**

- 界面填的 key 经 Electron `safeStorage` 加密后存进应用数据目录的 `config.json`
  （Windows 走 DPAPI、macOS 走 Keychain、Linux 走 keyring），落盘字段是 `apiKeyEncrypted`。
- 渲染进程拿到的是**脱敏快照**：配置里根本没有密钥字段，只有一个枚举说明「来自环境变量 /
  已加密保存 / 明文保存 / 无法解密 / 未设置」。
- 提交配置时，**没提到某个插件的密钥就保持原值**，传 `null` 才清除——
  这样改个模型名不会顺手把密钥抹掉。
- 密钥由别的机器或别的系统用户加密时，解密会失败：此时按「没有密钥」处理并提示重新填写，**不会崩溃**。
- 旧版本留下的明文 key 会在启动时自动改写为密文。
- 若平台没有可用的安全密钥库（例如没有 keyring 的 Linux），应用**拒绝保存密钥**并建议改用环境变量，
  而不是悄悄退回明文；确实要明文保存需显式设置 `RESEARCHER_ALLOW_PLAINTEXT_KEY=1`，界面会持续警告。

命令行没有 `safeStorage`：读到桌面应用加密的配置时会提示「解不开，请用环境变量」，绝不把密文当密钥发出去。

## 密钥泄漏防护

三层，任何一层命中都会失败：

1. `.gitignore` 覆盖 `.env*`、`config.json`、`*.pem`、`*.key`、`.researcher/` 等。
2. `tests/no-secrets.spec.ts`：断言被跟踪文件里没有密钥，且没有把运行时数据/配置文件纳入版本控制。
3. `scripts/scan-secrets.ts`：扫工作树 **+ 全量历史**，CI 与本地都可用。

扫描器是仓库内自有的、零依赖的一份实现（`tools/secret-scan.ts`），规则偏向「宁可漏报也不误报」——
告警一多就会被忽略。要放行只能显式加入 `ALLOWED_LITERALS`，或在那一行写 `secret-scan:allow`。

> 顺带说明：历史上从未提交过真实密钥（扫描全量历史可验证）。

## 命令行

引擎与 Electron 无关，可以直接在命令行跑：

```bash
node scripts/run-example.ts "你想研究的问题"                    # 走真实网络
node scripts/run-example.ts --offline                          # 用录制夹具，不联网
node scripts/run-example.ts "问题" --save-example               # 顺便写进 examples/
node scripts/run-example.ts --offline --format md               # 只产出 markdown（支持 md/json/html）

```

## 产物

每次运行写入 `<数据目录>/runs/<run-id>/`，append-only：

| 文件 | 内容 |
|---|---|
| `report.md` | Markdown 报告（引用编号对应来源清单；含资料地图概要与调研过程） |
| `report.html` | 自包含单文件 HTML（内联 CSS，可直接打印成 PDF） |
| `report.json` | 结构化报告原文快照 |
| `materials.md` | **资料文件**：证据本体——主题、逐字引文、盲区、分歧、语料清单（含逐篇抽取实现） |
| `materials.json` | 同一份内容的机器可读版本（带「每条语料被哪些主题引用」） |
| `provenance.json` | 本次实际使用的插件、模型、token 用量、降级原因、代理式观测 |
| `events.jsonl` | 完整事件流，事后排查以它为准 |
| `export.json` | 启用 `output-json` 时输出：报告 + 引用索引 |

**报告与资料文件是两件东西**：报告是**成品**（按模板组织的正文），资料文件是**证据本体**。
要核对某个结论时看资料文件，要看结论本身时看报告。

示例产物见 [`examples/`](examples/)。

## 拿到 key 之后：怎么验证代理式主流程

**这是目前唯一没有验证过的地方。** 机制层有端到端测试（用可编排的假模型跑通全链路），
但**提示词在真实模型上的效果从未跑过**——开发环境没有 key。
下面这份清单就是补这一课的办法：

```bash
# 1. 配置 key（环境变量，或应用内「设置」里填）
export DEEPSEEK_API_KEY=...          # Windows: $env:DEEPSEEK_API_KEY='...'

# 2. 跑一个你自己懂行的主题——懂行才能判断产出好不好
pnpm example "一个你熟悉的主题"
```

命令行会打印完整观测：不动点迭代几轮、搜索几轮、地图多大、几次工具调用、多少 token、
以及**每个任务因为什么停下**。逐项核对：

| 看什么 | 好是什么样 | 不好说明什么 |
|---|---|---|
| 搜索轮数 | 2–4 轮就饱和 | 一直搜不停：饱和阈值太松，或查询没在转向 |
| 地图主题数 | 若干**互不重复**的主题 | 一堆同义节点：归纳提示词需要加「合并同一方面」的约束 |
| 盲区（gaps） | 有具体、可回答的缺口 | 空着：模型没在批判性看覆盖度 |
| 大纲节数 | 与地图主题对得上 | 少很多：大纲没吃下地图（`minSupport` 可能过严） |
| 引用 | 点开每条都是真的、能对上正文 | 有编造 → 引用白名单过滤失效，属于 bug |
| 工具调用 | 集中在资料薄的那几节 | 全程 0 次：模型没在用工具，提示词要调 |

再把资料文件读一遍（`<run 目录>/materials.md`）：里面的逐字引文是否真的出现在对应来源里。

最后跑第二次同一个主题，确认**复用了缓存、只补新增**：

```bash
pnpm example "同一个主题"      # 观测里应出现「复用话题缓存」
```

把不满意的输出留档（连 `provenance.json` 一起），据此改提示词——
提示词在 `src/main/engine/agent/*-task.ts` 的顶部常量里。

**资料文件**（引用链完整、被过滤条目保留并标注原因）、
**话题缓存**（id 稳定性、损坏容错、原子写入、**第二次只抓新增**）、
抓取重试策略（含「4xx 不重试」「取消不重试」）、
**密钥存储**（明文不落盘、密文解不开时优雅降级、来源判定、脱敏快照、明文迁移）、
**仓库不含密钥**、输出失败隔离与格式筛选、源码可被 Node 直接执行（类型剥离兼容）、
输出渲染、内核端到端（含**零 key 全链路**与**代理式全链路**）、
以及 IPC 契约（含「每个通道都必须注册 handler」与产物路径越界校验）。

### 真实页面回归网

`fixtures/pages/` 里是四个真实页面的快照（约 385 KB），测试离线断言
**每页最终选中了哪个抽取器**，并检查三个正常站点的结果里**没有**站点自身的框架文字
（「最新推荐文章」「您可以按照自己的节奏」「Main page」），
以及 devsite 那页确实触发闸门回退、且**正文标题仍在**（宁可带噪声也不丢内容）。

夹具由 `scripts/record-page-fixtures.ts` 录制：逐级精简，**一旦决策会变就停手**——
Readability 是按 DOM 结构打分的，裁过头就等于在测一个线上不会走的路径。
录制时还会**抹掉密钥形态字符串**（真实页面源码里内嵌客户端公开密钥），
掩码保持原长度、用不在任何规则字符类里的字符，并复查确认无残留。
重录：`node --no-warnings scripts/record-page-fixtures.ts`。

界面与真实加密由 `pnpm smoke:ui` 验证：启动打包后的应用，通过 DevTools 协议读取真实 DOM，
确认 preload 桥已注入、界面渲染出内容、IPC 可以往返，并写入一个测试密钥后断言
**磁盘上是密文、没有明文**（结束后按字节还原用户的配置）。

## 已知限制

- **代理式主流程需要大模型 key，提示词在真实模型上的效果尚未验证**。
  机制层面有端到端测试覆盖（用可编排的假模型跑通采集→归纳→大纲→工具循环写作→输出、
  引用链完整性、饱和终止、话题复用、降级链），但**提示词好不好用没跑过**。
  这是最大的未验证面；补课办法见上面「拿到 key 之后」那一节的清单。
- **未做运行时热加载**：加插件需要重新构建。运行期选型已支持，热加载是后续扩展。
- **仅抓取静态 HTML**：不执行 JS，纯前端渲染的页面会抓到空正文。
  本应用已经内置 Chromium，用真实 DOM 渲染再抽取是很自然的下一步。
- **单一并发运行**：同一时刻只允许一次运行。
- **话题缓存按查询文本匹配**：措辞不同但意思相同的话题会各存一份，不做语义合并。
- **地图归纳的质量取决于模型**：它只做归纳不淘汰，所以模型偷懒时地图会偏薄，而不是丢资料。
- **抽取是启发式的**：Readability 加比例闸门能分开实测样本，但不可能对所有站点都对；
  因此闸门可配，且报告里逐篇写明用了哪个实现。
- 部分站点会拒绝抓取（实测知乎返回 403）。这类失败会逐条记入报告的「抓取失败」，
  不会影响其余来源，也不会中断运行。

### 关于 DuckDuckGo 与"网络不可达"

开发过程中曾出现过 `duckduckgo.com` 连接失败，一度被判断为「该网络封锁了 DuckDuckGo」。
**这个判断是错的**，记录在此以免重蹈覆辙：

- 真实原因：开发机上所有域名都解析到 `198.18.0.0/15`（RFC 2544 基准段，常被代理软件用作
  fake-IP 池），说明存在**透明出口代理**；该代理会**偶发丢掉 TLS 握手**
  （`Client network socket disconnected before secure TLS connection was established`）。
- 复测结果：连续 6 次请求 DuckDuckGo 全部 HTTP 200，且一次真实的在线全链路运行成功
  （8 个来源 → 抓取 5 篇 → 产出报告）。
- 代码层面的真问题不是「DDG 不可用」，而是**当时一次失败就终止整轮运行**——已修复（见「抓取重试」）。

因此：零 key 全链路**既**有录制夹具保证可复现，**也**能在真实网络下端到端跑通。

## 抓取重试

`fetch.maxRetries`（默认 2）只对**瞬时**故障重试：连接被重置、TLS 握手被丢、超时、HTTP 429、5xx。
4xx 是请求本身的问题，不重试；用户取消也不重试。每次重试都会写进运行日志，
所以在界面的日志面板里能看到「为什么这次慢了」。
