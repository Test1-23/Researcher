# Researcher — 设计

状态：**M0–M5 已实现**。本文记录架构决策与理由，实现细节以代码为准。

---

## 1 目标

把「用大模型做资料调研」从一次性对话，变成一条**可替换、可复现、可追溯**的流水线：

1. 用户输入问题，得到带引用、带来源状态的合成报告。
2. 主流程、搜索、整理、输出**四类角色全部是插件**，换后端只改配置。
3. 零 API key 也能端到端跑通。
4. 报告必须诚实：写清用了哪个插件、哪些来源失败、哪里降级了。

## 2 关键决策与理由

| 决策 | 选择 | 理由 |
|---|---|---|
| 引擎语言 | TypeScript / Node | Electron 主进程、渲染进程、插件同一种语言；无需跨进程桥接引擎 |
| 插件加载 | 编译期静态注册，**运行期选型** | 与 DSH 一致：可替换性来自统一接口 + 运行期选择，而非热加载第三方代码 |
| 契约位置 | 单一 `engine/types.ts` | 插件只依赖它，因此插件之间零耦合；换任一插件不影响其它插件 |
| 抓取为何不做成插件 | 内核内置服务 | 抓取+正文抽取是通用管道能力，不是领域逻辑；用户只要求 4 类插件 |
| 整理的输出形态 | 结构化 JSON 而非散文 | 结构可校验、可过滤编造引用、可被不同输出插件复用 |
| 默认整理策略 | 抽取式（`organize-extractive`）为零 key 兜底，LLM 为质量升级 | 保证「装了就能用」，同时给出升级路径 |
| 与旧讲座生成器的关系 | 只保留「插件内核」与「诚实记录」两条原则 | 数学对象、表格校验等是领域逻辑，与本产品无关 |

## 3 分层

```
┌──────────────────────────────────────────────────────────────┐
│ Electron 主进程   窗口、IPC、生命周期                          │
├──────────────────────────────────────────────────────────────┤
│ 内核 engine/      注册表 · 选型 · 配置 · run 仓库 · 事件 · 抓取  │  ← 不认识 Electron
├──────────────────────────────────────────────────────────────┤
│ 契约 types.ts     SearchProvider / LlmProvider / Organizer /  │  ← 插件只依赖这一层
│                   OutputPlugin / Pipeline / PluginContext     │
├──────────────────────────────────────────────────────────────┤
│ 自主任务 agent/   黑板 · 运行器 · 搜索/大纲/写作三个任务         │
├──────────────────────────────────────────────────────────────┤
│ 插件 plugins/     内置实现，互不 import                        │
└──────────────────────────────────────────────────────────────┘
```

内核与 Electron 完全解耦，因此 `scripts/run-example.ts` 能用同一个内核在命令行跑完整个流程。

## 4 代理式主流程：任务 + 黑板 + 不动点迭代

**这一节记录了本项目最重要的一次设计修正。** 最初我把主流程做成「阶段序列」——
第 1 步搜索、第 2 步抓取、第 3 步整理。那不是 agent，那是戴着 agent 帽子的脚本：
它给每个阶段下死目标（搜 3 轮、抓 8 篇），遇到意外不会转向。

改成：**每个 agent 是一个任务，拥有目标 + 自己观测得到的终止条件**，任务之间只通过黑板协作。

### 4.1 黑板

唯一共享状态，靠「只暴露受控 mutator」在结构上保证两条性质：

- **地图只增不减**：任务无法替换 map，只能 merge；已有 sourceIds / claims 只做并集。
- **每次变更都进 journal 并推进 revision**：于是「这一轮有没有变化」可被运行器观测。

另有一个**只在地图/语料真的变化时**才递增的 `mapRevision`。这不是冗余：
`revision` 连记一条观测都会推进，用它判断「大纲是否过期」会让大纲一写完就被判为过期。

### 4.2 运行器

```
循环：
  未满足 = 所有 isSatisfied(board) 为假的任务
  未满足为空 → 收敛，结束
  本轮黑板毫无变化 → 判定无进展，如实报告后结束
  否则 → 让未满足的任务各走一步（顺序执行，后者能看到前者刚写的）
  护栏：全局迭代上限
```

任务可以**互相重新激活**：大纲发现某节支撑不足时写一条缺口请求，搜索任务看到未处理的请求
就重新变得未满足。整轮在所有任务同时满足时结束——终止是**涌现**的，不是编排写死的。

三种收尾都会被如实区分：`converged` / `stalled`（连续多轮零变化）/ `limits`（撞护栏，
**条件未满足**）。撞护栏时报告里写明「未满足的条件是什么」，绝不假装完成。

### 4.3 三个任务

| 任务 | 终止条件（观测得到） | 它能做什么 |
|---|---|---|
| 搜索 | 连续 N 轮贡献率低于阈值，且无未处理缺口请求 | 盲区驱动查询、多轮检索、去重、判无关、归纳进地图 |
| 大纲 | 覆盖度：固定节在位、可展开节够数、每节支撑足、地图无遗漏 | 起草/修订大纲；**不自己搜**，只写缺口请求 |
| 写作 | 全部小节写出来且通过自检 | 工具循环：补搜 / 回读原文 / 改大纲 |

「搜索不替大纲搜、大纲不替搜索想」是刻意的：**任务之间只通过黑板协作**，
谁该干活由运行器按满足状态决定。

### 4.4 为什么筛选只淘汰重复与无关

从结果倒推：写作要的资料质量要求不苛刻、但格式严格；大纲需要结构化且全面的视野；
搜索要的是广度与深度。**淘汰赛会主动杀掉大纲唯一需要的广度**，
而且被淘汰的东西大纲再也看不到，它就无从知道这个话题由哪些方面构成、哪里存在分歧。

所以过滤只做确定性去重 + 让模型挑「无关」项，且提示词明确禁止按质量排名。
判定失败时整批保留——多留噪声的代价远小于误删资料。被过滤的条目仍进报告并标注原因。

### 4.5 正文抽取

Readability（现成算法）优先，低于闸门时回退到整页纯文本。回退刻意不做第二个启发式抽取器：
下游是 LLM，噪声可忽略；而猜错正文的抽取器会**主动丢内容**，那不可挽回。

### 4.6 话题缓存与复用

按话题存语料与地图。复用**不需要特例**：地图已填满正是搜索任务原本就认作饱和的条件，
于是它自己就早收工。缓存读不出来时从零开始（持久化是加速手段，不是正确性依赖），
写入用临时文件 + rename。

## 5 一次运行的时序

```
kernel.run(input, bus, signal)
  ├─ 校验查询
  ├─ 解析主流程：pipeline-research 不可用 → 降到 pipeline-default
  ├─ 建 run 目录，事件同时落盘 events.jsonl
  ├─ emit run:start
  └─ pipeline.run(input, ctx, signal)
       ├─ [research] 装配黑板与三个任务 → 跑到不动点 → 组装 Report
       ├─ 写回话题缓存
       └─ [output]   按 formats 筛选 → 逐个 render（失败隔离）
  ├─ 写 report.json / provenance.json
  └─ emit run:done（必须是最后一个事件）
```

## 6 插件契约要点

```ts
interface SearchProvider {
  readonly id: string
  readonly kind: 'search'
  available(ctx: AvailabilityContext): boolean      // 纯本地检查，禁止网络
  search(req, ctx: PluginContext, signal?): Promise<SearchResult>
}
```

**为什么 `available()` 接受一个上下文对象而不是零参数**：
`organize-llm` 自己不需要 key，但它**依赖**大模型 provider 可用。
把「查询另一个插件是否可用」的能力交给内核（而不是让它 import provider），
既解决了依赖判断，又没有破坏「插件之间零耦合」。内核用 `seen` 集合防止配置写出循环依赖时无限递归。

`pipeline` 类别也走同一套：`pipeline-research` 声明自己依赖 provider，没有 key 时内核自动降级——
**「零 key 依然能跑」不是特例代码，而是选型机制的自然结果**。

**为什么所有方法都接收 `ctx`**：搜索插件需要 HTTP、LLM 插件需要配置、
输出插件需要写产物、话题缓存需要数据根目录。统一传 `ctx` 比给每个方法设计不同的注入方式更简单。

**为什么 provider 有 `supportsTools`**：不是每个 OpenAI 兼容后端都实现原生工具调用。
不支持时写作任务降级为无工具模式并如实记录，而不是用提示词模拟工具调用——
那正是「不该手写」的同一个错误。

## 7 失败与降级策略

| 情形 | 行为 |
|---|---|
| 主流程不可用（无大模型） | 降到配置的备用主流程；日志写明降级 |
| 主搜索插件不可用 | 用配置的备用插件；`provenance.searchFallbackUsed = true` |
| 搜索插件运行期抛错 | 整次运行失败（没有来源就无事可做），错误码 `SEARCH_FAILED` |
| 单个来源抓取失败 | 记入 `failures`，整理阶段只用成功正文，报告里逐条标注 |
| LLM 输出非法 JSON | 追加修复指令重试一次；仍失败 → 降级到备用整理插件并记录原因 |
| 用户取消 | `AbortSignal` 贯穿全部阶段；抛 `CANCELLED`，已落盘产物保留 |
| 429 限流 | 带退避重试一次（LLM provider）；仍失败则作为类型化错误上报 |
| 瞬时网络故障 | 抓取层按 `fetch.maxRetries` 重试（连接重置、TLS 握手被丢、超时、429、5xx）；4xx 与取消不重试 |
| 配置损坏 | 备份为 `config.json.bad`，回退缺省配置，不让应用起不来 |

## 8 安全与诚实

- **渲染进程**：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`；
  只通过 preload 暴露的窄接口访问主进程；CSP 限制到 `'self'`。
- **报告正文一律当文本渲染**，不用 `dangerouslySetInnerHTML`——抓来的网页里带脚本也不会被执行。
- **API key 加密存储**（见 §8）。
- **日志脱敏**：日志与事件在写出去之前，会把配置里出现的 key 字面量替换成 `***`。
- **产物路径**：读写前先与 run 仓库的真实产物清单比对，拒绝越界路径。
- **诚实性不是可选项**：`provenance` 记录实际使用的插件与降级原因；
  抽取式整理的摘要里写明「未经大模型改写，不代表对来源内容的判断」。

## 9 密钥存储

密钥处理的原则是**明文只在内存里存在**：

```
界面输入 ──IPC 脱敏快照──▶ 渲染进程（只拿到「来自哪里」的枚举）
   │
   └─▶ 主进程内存 config ──SecretCodec.encrypt──▶ config.json: apiKeyEncrypted
                ▲
                └── SecretCodec.decrypt ── 插件通过 ctx.config 读到的仍是 apiKey
```

- **加解密是注入给配置层的接缝**：`engine/config.ts` 只定义 `SecretCodec` 接口，
  因此内核依旧不认识 Electron。桌面应用注入 safeStorage 实现，命令行与测试注入明文实现。
- **`config:get` 返回脱敏快照**，密钥字段（明文与密文）都被抹掉，只留 `SecretSource` 枚举。
- **`config:set` 的密钥语义是显式的**：键缺省 = 保持原值，`null` = 清除，非空字符串 = 设置。
  「缺省即保持」很关键——否则每次改个模型名都会把密钥抹掉。
- **解密失败不是致命错误**：配置可能来自另一台机器或另一个系统用户。
  此时按「没有密钥」处理并让界面提示重新填写。
- **平台不支持安全存储时拒绝保存**，而不是静默退回明文；逃生开关
  `RESEARCHER_ALLOW_PLAINTEXT_KEY=1` 会让界面持续显示明文警告。

## 10 已知限制与后续方向

- **提示词在真实模型上的效果未经验证**：机制有端到端测试覆盖（假模型跑通全链路），
  但「换成真模型能不能写出好东西」没有验证过——本次改动最大的未验证面。
- 插件热加载（当前需要重新构建）。
- 搜索适配器只实现了 DeepSeek 与 DuckDuckGo；Tavily / Exa / Brave 只是再写一个适配器。
- 抓取不执行 JS，纯前端渲染页面会抓到空正文；可换成无头浏览器或第三方抽取服务。
  **本应用已经内置 Chromium**，用真实 DOM 渲染再抽取是很自然的下一步。
- 话题缓存按查询文本匹配，不做语义合并。
- 输出插件之间没有写入路径冲突检测（两个插件写同一文件会互相覆盖）。
- 流式整理（边生成边显示）。
- PDF 导出与打包分发。
